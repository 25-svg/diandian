# 提示词三：企业母稿升级比较设计

## 1. 目标

提示词三负责回答一个独立问题：已经通过片段质量评分的话术，相对当前企业母稿究竟带来了什么新价值，以及应当怎样处理。

它不再重复提示词二的质量评分，也不以文字相似度代替业务判断。正式流程为：

1. 提示词一发现训练价值片段。
2. 提示词二按片段类型评分。
3. 仅当提示词二的确定性决策为 `support_candidate` 或 `golden_sentence` 时，自动执行提示词三。
4. 提示词三判断新增、金句、替换、合并、重复或拒绝。
5. 人工审核新增、替换和合并建议。
6. 只有人工确认的内容才能生成下一版企业母稿。

## 2. 不在本阶段解决的问题

- 不接入订单、点击、停留、转化率等真实经营数据。
- 不把话术评分描述成真实成交效果。
- 不自动发布新版母稿。
- 不允许模型直接覆盖母稿原文。
- 不把建议改写稿冒充主播原话。
- 不为 85 分以下片段调用提示词三。

## 3. 输入

### 3.1 候选话术

候选输入必须来自提示词二的结构化结果，并包含：

- 片段编号和类型。
- 主播原话。
- 提示词二总分、证据等级和风险状态。
- 值得保留的地方。
- 待改进内容和待确认事实。
- 可复用原话。
- 建议训练稿。
- 推荐母稿章节。
- 真实逐字稿证据。

### 3.2 企业母稿相关章节

系统使用提示词二已经匹配并评分的同一个已发布母稿版本和章节，不允许提示词三自行切换母稿：

- 母稿编号、版本和章节编号。
- 章节标题、类型和正式话术。
- 商品卡编号（如有）。

## 4. 输出合同

模型必须返回以下字段：

```json
{
  "comparison_decision": "add_as_support",
  "matched_master_section": "异议处理/质量担忧",
  "same_scene": true,
  "new_value": "候选话术比母稿新增的具体价值",
  "why_better": ["具体理由"],
  "duplicate_content": ["与母稿重复的部分"],
  "risk_or_uncertainty": ["仍需人工确认的内容"],
  "original_host_words": "主播原话",
  "training_suggestion": "建议表达，不得冒充主播原话",
  "recommended_action": "建议放入哪个章节以及如何使用"
}
```

`comparison_decision` 只允许：

- `add_as_support`
- `add_as_golden_sentence`
- `replace_existing`
- `merge_with_existing`
- `duplicate`
- `reject`

数组字段即使只有一项也必须返回数组。解析器应兼容 Markdown 代码围栏和单条字符串误写为数组字段，但不能容忍未知决策、缺失关键字段或错误类型。

## 5. 后端确定性规则

模型只提供比较判断，最终处理权限由后端决定：

1. 提示词二决策不是 `support_candidate` 或 `golden_sentence`：不调用提示词三。
2. 提示词二风险为 `blocked` 或证据为 `C`：不调用提示词三。
3. `add_as_golden_sentence` 只允许提示词二决策为 `golden_sentence`。
4. `add_as_support` 只允许提示词二决策为 `support_candidate`。
5. `replace_existing` 和 `merge_with_existing` 只能标记为“建议人工审核”，不能自动改母稿。
6. `duplicate` 和 `reject` 不进入候选升级队列，但保留比较结果。
7. 模型返回的主播原话必须能在候选原话中找到，否则比较结果无效。
8. 模型返回的母稿章节必须与请求中的已匹配章节一致，否则比较结果无效。
9. 存在未确认的商品、价格、库存、链接、售后或成交事实时，结果必须显示风险提示；系统不得把这些内容写成企业事实。

## 6. 数据持久化

比较结果随候选片段保存，至少包含：

- 比较决策。
- 匹配母稿和章节。
- 新增价值。
- 优于母稿的理由。
- 重复内容。
- 风险和不确定项。
- 主播原话。
- 明确标识的建议稿。
- 推荐动作。
- 使用的母稿版本。
- 创建时间。

同一片段、同一母稿版本的提示词三结果必须幂等。企业母稿升级后，旧比较结果保留用于审计，但标记为基于旧版母稿，不得直接用于新版升级。

## 7. 页面呈现

小白页面只显示一个“与企业母稿比较”结论区：

- 顶部使用中文结论：新增辅稿、加入金句、建议替换、建议合并、内容重复或不建议采用。
- 显示“新增了什么”和“为什么更好”。
- 显示“与母稿重复的内容”。
- 显示“使用前还要确认”。
- 分开展示“主播原话”和“建议稿”。
- 显示下一步按钮或说明。

不得直接显示模型 JSON。`replace_existing` 和 `merge_with_existing` 使用“提交人工审核”措辞，不使用“已替换”或“已合并”。

## 8. 与候选辅稿队列的关系

- `add_as_support`：进入候选辅稿人工审核。
- `add_as_golden_sentence`：进入金句话术人工审核分组。
- `replace_existing`：进入“建议替换”人工审核分组。
- `merge_with_existing`：进入“建议合并”人工审核分组。
- `duplicate`：显示为重复，不进入升级选择。
- `reject`：显示为不采用，不进入升级选择。

人工审核通过前，任何结果都不是企业母稿内容。

## 9. 错误处理

- 模型 JSON 首次解析失败时，只允许一次格式修复重试。
- 修复提示不得改变决策、原话、证据或风险。
- 两次解析失败后保留提示词二结果，显示“母稿比较暂未完成”，允许单独重试提示词三。
- 不重新进行 ASR、不重新发现片段、不重复执行提示词二。
- 网络失败不得删除候选片段或已有比较记录。

## 10. 测试标准

### 10.1 领域测试

- 六种决策均能解析。
- 未知决策被拒绝。
- 单条字符串列表可规范为数组。
- 代码围栏 JSON 可解析。
- 主播原话不属于候选原话时被拒绝。
- 母稿章节不一致时被拒绝。

### 10.2 流程边界

- 84 分不调用提示词三。
- 85 分但证据 C 不调用。
- 风险 `blocked` 不调用。
- `support_candidate` 和 `golden_sentence` 自动调用。
- `replace_existing`、`merge_with_existing` 不自动修改母稿。
- `duplicate`、`reject` 不进入升级队列。
- 母稿版本变化后旧结果不可直接发布。

### 10.3 前端测试

- 显示中文决策和下一步。
- 主播原话与建议稿有明显边界。
- 不渲染原始 JSON。
- 网络失败只显示可重试状态，不影响提示词二结果。

## 11. 验收结果

用户打开复盘片段后，可以依次看到：

1. 提示词二的唯一正式话术质量分。
2. 提示词三的“相对企业母稿如何处理”结论。
3. 清楚的新增价值、重复内容、风险和下一步动作。

达到 85 分不再等于自动进入母稿；只有经过提示词三比较并通过人工审核后，候选内容才有资格参与下一版企业母稿生成。
