# 直播数据大屏：官方 XLSX 自动导入设计

## 目标

在没有抖店直播数据 API 权限时，主播仍可通过官方“整场数据下载”导出 XLSX。桌面端自动发现并导入下载文件，在“直播数据大屏”展示本场和历史直播指标。

日常流程：主播仅需在罗盘点击一次下载；软件自动导入。不实现网页登录、Cookie 抓取或自动下载。

## 范围

本期新增：

- 独立“直播数据大屏”菜单与页面。
- 下载目录设置，默认系统 Downloads 目录。
- 下载目录监听与手动选择 XLSX 的兜底导入。
- 官方整场数据 XLSX 的校验、解析、去重、持久化和导入记录。
- 本场核心指标、渠道分析、短视频引流、商品明细、历史场次趋势展示。

本期不做：

- 自动登录罗盘、自动点击下载、读取浏览器 Cookie 或网页抓取。
- 未出现在 XLSX 中的直播指标推算或伪造。
- SKU 子行的独立统计；本期只保存商品汇总行。

## 数据输入与字段

只接受官方整场导出文件。校验文件具有以下工作表：

- `基本信息`
- `整体看板`
- `流量分析-流量转化`
- `流量分析-渠道分析`
- `流量分析-短视频引流`
- `商品分析-商品明细`

导入器读取：

- 基本信息：店铺、抖音号、开播时间、直播时长、用户支付金额、千次观看用户支付金额。
- 整体看板：观看人数、平均/最高在线、商品点击、转化率、观看时长、粉丝、互动、客单价、退款。
- 渠道分析：渠道的观看、支付、订单、转化和千川消耗。
- 短视频引流：视频标题、发布时间、曝光、引流、点击率。
- 商品明细：商品汇总行的商品 ID、名称、支付金额、成交、曝光、点击、退款。

金额解析为分或 Decimal 兼容格式；百分比解析为小数；时长解析为秒。原始文件名和校验摘要写入导入记录以便追溯。

## 数据模型

新增直播场次主表，唯一键为 `账号标识 + 开播开始时间`。主表保存核心指标、来源文件信息和导入时间。

新增关联表：渠道指标、短视频引流、商品汇总和导入记录。重复导入同一场次时执行幂等更新：替换本场的关联明细，不产生重复行。

解析失败不写入业务表，只新增失败导入记录并在页面显示可读原因。

## 导入流程

1. 应用启动后读取下载目录设置；不存在时使用 Downloads。
2. 监听目录中新出现或变更的 `.xlsx` 文件。
3. 忽略 Office 临时文件（`~$` 前缀）；等待文件大小在短时间窗口内稳定，再开始读取。
4. 校验工作表与表头；不符合官方结构时标记为“不支持的文件”，不导入。
5. 解析数据、规范化单位、按唯一键去重并持久化。
6. 发出刷新事件，直播数据大屏显示最新导入结果。
7. 监听失败或用户需要补录时，可通过“导入 XLSX”按钮使用相同导入器。

未来自动下载模块只负责把下载完成的官方 XLSX 放入同一下载目录；不修改解析、存储或页面逻辑。

## 页面设计

“直播数据大屏”包括：

- 顶部：最新场次选择、导入状态、手动导入和下载目录设置入口。
- 核心指标：用户支付金额、千次观看支付金额、观看人数、平均在线、成交人数、成交订单、观看成交率、商品点击成交率、人均观看时长、千川消耗（存在时）。
- 分析区域：渠道表现表、商品成交榜、短视频引流榜、历史场次趋势。
- 数据说明：显示来源文件、导入时间，以及 XLSX 未提供的指标“不提供”。

支付金额必须按官方字段名展示；不得将“用户支付金额”标记为“直播间成交金额”。

## 错误处理

- 文件仍在下载：延后重试，不显示失败。
- 文件损坏、加密或表头不匹配：不写入场次数据，提示用户重新下载官方 XLSX。
- 同一场次重复下载：更新数据，页面提示“已更新已有场次”。
- 下载目录不可访问：停止监听并提示用户重新选择目录；手动导入保持可用。

## 测试与验收

- 单元测试：金额、百分比、时长、直播时间、商品汇总行和 SKU 子行识别。
- 集成测试：有效工作簿导入、重复导入幂等、缺失工作表拒绝、临时文件忽略。
- 前端测试：核心指标字段映射和无数据展示。
- 手动验收：将官方导出的 XLSX 下载到指定目录后，大屏无需选择文件即可更新；再次下载同一场次不产生重复记录。
