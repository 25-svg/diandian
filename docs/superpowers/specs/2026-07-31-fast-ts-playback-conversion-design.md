# TS 快速可播放版本设计

## 目标

缩短 TS 首次可播放时间，并让转码状态显示真实百分比、速度与预计剩余时间。

## 当前瓶颈

播放副本任务会先等待逐字稿任务并获取媒体锁，之后才检测视频编码。常见 H.264/AAC TS 即使只需无损封装，也被不必要地延后。完整重编码路径只优先尝试 AMD AMF，而项目已有可验证的 NVIDIA、Intel、AMD 编码器选择器未被复用。进度仅显示已处理媒体时间。

## 设计

1. 任务开始立刻探测媒体元数据。
2. H.264 + 浏览器支持音频的 TS 走快速封装：`-c copy`、MP4 faststart；不等待 ASR 媒体锁。原始 TS 保留。
3. 不兼容视频才进入重编码：使用 `hwaccel::get_x264_encoder()` 的可用硬件编码器；如果没有可用硬件编码器，再使用 `libx264` 快速参数。
4. 重编码输入若音频已是 AAC、MP3 或 MP2，则复制音频；否则转 AAC。
5. 转码进度基于 ffprobe 总时长和 FFmpeg 已处理时间，显示百分比、实时倍率和 ETA。快速封装显示已复制数据量与百分比。

## 约束

- 不降低分辨率，不自动裁剪，不删除原文件。
- 不让重编码与逐字稿识别并发占用同一媒体锁。
- 快速封装失败时，回退到相同硬件选择的重编码流程。
- 所有输出继续使用 `.playable.mp4`，完成后才提供给播放器。

## 验收

- H.264/AAC TS 在没有 ASR 等待时立即封装并可播放。
- H.265 TS 使用经验证的可用硬件编码器，无法使用时才走 CPU。
- 任务页持续显示百分比、倍率、预计剩余时间。
- 已有播放副本、重复请求、失败回退行为不变。
