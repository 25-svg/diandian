# 候选片段分类评分 V2 设计

## 目标

提示词一负责从整场逐字稿中发现有训练价值的候选片段。提示词二负责对每个候选片段进行唯一一次正式评分，并决定它属于候选辅稿、金句话术、训练素材、复盘参考还是禁止使用。

本次升级解决两个问题：

1. 旧评分器只允许完整成交链路进入评分，导致金句、异议处理、留人钩子等局部优质话术被直接判低或不评分。
2. 页面同时出现发现分和母稿分，普通使用者无法判断应该相信哪个分数。

升级后，提示词一产生的发现置信度只用于内部排序；提示词二产生的“企业母稿可复用价值分”是页面唯一正式分数。

## 范围

本次修改包括：

- 12 种片段类型的分类评分目标。
- 六项、总计 100 分的正式评分模型。
- 证据等级、风险状态和使用结论。
- 后端确定性校验与入选规则。
- 与企业母稿章节及已确认商品事实的评分输入。
- 小白可读的评分结果展示。
- 满足条件的候选辅稿进入现有人工审核队列。

本次不包括：

- 自动合并候选辅稿到企业母稿。
- 独立金句话术库的持久化和管理页面。
- 订单、点击、停留等真实经营数据评分。
- 修改提示词一的候选发现规则。

## 片段类型与评价目标

| 片段类型 | 主要评价目标 |
| --- | --- |
| 完整成交链路 | 需求到成交确认是否完整、自然、可复用 |
| 高质量金句 | 说服力、自然度和可直接复用程度，不因链路不完整扣低分 |
| 需求判断 | 是否准确识别预算、用途、偏好和顾虑 |
| 产品推荐 | 推荐是否匹配客户需求，推荐理由是否清楚 |
| 产品讲解 | 信息是否准确，是否把参数转化为用户价值 |
| 异议处理 | 是否理解顾虑、提供可信证据并推动下一步 |
| 留人钩子 | 是否给出继续停留的明确收益或期待 |
| 信任建立 | 是否通过检测、成色、来源、售后或发货承诺降低风险 |
| 售后与风险消除 | 承诺是否真实、具体并能降低客户顾虑 |
| 价格、优惠或链接承接 | 价格、优惠、链接和商品是否明确对应 |
| 催单与成交确认 | 是否有明确行动指令和真实成交证据 |
| 需要改进的反面案例 | 识别问题和训练价值，禁止进入候选辅稿 |

## 正式评分模型

正式总分为 100 分：

| 维度 | 上限 |
| --- | ---: |
| 场景目标完成度 | 30 |
| 话术说服力 | 20 |
| 相对企业母稿的增量价值 | 20 |
| 可直接复用程度 | 15 |
| 证据与事实准确性 | 10 |
| 表达简洁自然度 | 5 |

每个维度必须包含：

- 实际得分。
- 分数上限。
- 简短、可理解的评分理由。
- 当前片段中的真实时间和原话证据。

后端验证每项分数上限并重新计算总分。模型输出的总分与后端计算结果不一致时，以后端结果为准。

## 证据与风险

证据等级：

- `A`：关键信息在逐字稿和已确认资料中均有明确证据。
- `B`：主要内容有证据，少量商品或成交信息需要人工确认。
- `C`：关键事实缺失，只能作为观察素材。

风险状态：

- `passed`：无关键风险。
- `needs_review`：型号、价格、库存、链接或成交状态需要人工确认。
- `blocked`：存在事实冲突、违规承诺或严重误导。

模型不得补写逐字稿中没有出现的成交、价格、型号、库存、优惠、链接、售后或主播原话。未经确认的动态事实必须进入 `facts_to_confirm`。

## 决策规则

后端根据评分、证据等级、风险和片段类型重新计算最终结论，不直接信任模型给出的 `decision`：

1. 风险为 `blocked`：`blocked`。
2. 类型为“需要改进的反面案例”：
   - 存在严重风险时为 `blocked`。
   - 其他情况为 `reference_only`。
3. 类型为“高质量金句”，总分不低于 85、证据等级为 A 或 B、风险不是 blocked：`golden_sentence`。
4. 其他类型总分不低于 85、证据等级为 A 或 B、风险不是 blocked：`support_candidate`。
5. 总分 70～84：`training_material`。
6. 总分低于 70：`reference_only`。
7. 证据等级为 C 的片段不得成为 `support_candidate` 或 `golden_sentence`；即使超过 85 分，也降为 `training_material`。

只有 `support_candidate` 写入现有候选辅稿人工审核队列。`golden_sentence` 本阶段在分析页展示，不写入候选辅稿表。

## 数据流

1. 用户选择提示词一发现的候选片段。
2. 系统按片段场景自动匹配企业母稿章节。
3. 后端读取已审核逐字稿、匹配的企业母稿章节和已确认商品参数卡。
4. 后端调用提示词二，要求返回固定 JSON。
5. 解析器兼容代码块、数字字符串和单条文本误返回为数组的常见模型格式问题。
6. 后端验证证据引用、分数范围、证据等级和风险状态。
7. 后端重新计算总分和最终结论。
8. 页面显示唯一正式评分及小白化解释。
9. 符合规则的候选辅稿写入人工审核队列。

## 兼容策略

- 保留现有命令 `compare_highlight_to_master`，避免修改前端调用入口。
- 请求增加提示词一产生的候选片段结构，旧字段继续保留。
- 返回结果增加 V2 评分、证据和风险字段。
- 前端优先渲染 V2 结果；遇到旧缓存结果时使用旧版兼容展示。
- 现有候选辅稿表继续保存总分、入选状态和 JSON 明细，不进行破坏性数据库迁移。
- 历史候选记录不自动重新评分。

## 页面展示

评分区域按以下顺序展示：

1. 结论：候选辅稿、金句话术、训练素材、复盘参考或禁止使用。
2. 唯一正式总分：企业母稿可复用价值分。
3. 证据等级和风险状态。
4. “为什么好”：从模型结果中提炼的通俗短句。
5. “哪里需要改”：明确缺少的动作或不清楚的表达。
6. “还要确认”：商品和成交相关动态事实。
7. 六项评分明细，每项展示分数、理由和真实证据。
8. 主播可复用原话与明确标记的培训建议稿。
9. 建议放入企业母稿的章节。

页面不得再把提示词一的发现置信度显示成正式分数。

## 错误处理

- 模型 JSON 解析失败时自动进行一次只修格式、不改判断的重试。
- 分项超过上限、证据引用不属于当前片段或枚举值非法时，评分失败且不写入候选队列。
- 找不到企业母稿章节时，提示“未匹配企业母稿场景”，不生成增量价值分。
- 存在待确认关键逐字稿时允许展示分析，但风险至少为 `needs_review`，不得直接进入候选辅稿。
- 重复片段可以重新查看原评分，但不得重复写入候选辅稿。

## 测试

聚焦测试至少覆盖：

- 六项分数边界和总分计算。
- 12 类片段的类型目标进入提示词。
- 85 分、70 分和 69 分边界。
- A/B/C 证据等级门槛。
- `blocked` 风险强制禁止入选。
- 高质量金句进入 `golden_sentence`，不进入候选辅稿表。
- 反面案例不得进入候选辅稿。
- 单句金句不因缺少完整链路被拒绝评分。
- 非完整链路的异议处理等片段可以正常评分。
- 模型返回数字字符串、代码块和常见数组格式错误的兼容解析。
- 重复片段不重复入库。
- 旧结果仍能兼容显示。
