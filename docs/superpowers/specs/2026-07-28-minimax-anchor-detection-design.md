# MiniMax 录播主播自动识别设计

## 目标

录播或外部视频进入系统后，自动读取画面中持续显示的“主播 XX”字幕牌，将主播姓名写入录播记录并展示在录播列表。识别失败不能阻塞视频入库、NAS 转存、逐字稿转写或片段分析。

## 解决的问题

- 录播列表目前只能依赖人工备注判断主播，容易漏填或填错。
- `note` 同时承担业务备注和主播信息会造成含义混乱，不能继续复用。
- 单帧可能处于转场、遮挡或字幕动画中，直接识别容易误判。
- 自动结果和人工校正之间缺少优先级，重新识别可能覆盖已确认姓名。

## 范围

本期只实现：

1. 从录播画面读取明确可见的主播姓名。
2. 将结果写入视频专用字段。
3. 在录播列表显示识别状态、来源和姓名。
4. 支持人工修改，并锁定人工结果。
5. 支持失败后手动重试。

本期不实现：

- 人脸识别或根据长相、声音、衣服推断主播身份。
- 主播个人话术库。
- 主播绩效统计和主播间对比。
- 修改现有逐字稿、复盘和母稿使用的文本模型。

## 数据模型

在 `videos` 表增加：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `anchor_name` | TEXT | 已确认或自动识别出的主播姓名 |
| `anchor_source` | TEXT | `minimax_vision`、`manual` 或空 |
| `anchor_confidence` | TEXT | `high`、`medium`、`low` 或空 |
| `anchor_detection_status` | TEXT | `pending`、`running`、`confirmed`、`failed` |
| `anchor_detection_error` | TEXT | 最近一次失败的可读原因 |
| `anchor_detected_at` | TEXT | 最近识别或人工修改时间 |

人工修改后 `anchor_source = manual`。除非用户再次手动修改，否则自动任务不得覆盖人工结果。

## 识别流程

1. 视频入库后默认状态为 `pending`。
2. 录播列表加载时，后台按顺序处理待识别视频，避免同时调用多个模型请求。
3. 通过现有 canonical media resolver 获取本地或 NAS 中可读取的视频路径。
4. 根据视频时长选择 3 个分散时间点，避开开头和结尾：
   - 短视频：20%、50%、80%。
   - 长视频：10%、50%、90%，并限制在有效时长内。
5. 使用 FFmpeg 提取 3 张 JPEG 帧并转成 base64。
6. 一次请求发送给 `MiniMax-M3`，要求逐帧读取固定字幕牌。
7. 本地解析结构化 JSON，并执行一致性判断：
   - 至少 2 帧读到相同非空姓名：`confirmed/high`。
   - 只有 1 帧读到姓名或多帧冲突：`failed`，等待人工处理。
   - 所有帧均未发现字幕牌：`failed`。
8. 成功或失败均写回数据库，前端刷新对应行。

## 模型约束

系统提示必须明确：

- 只读取画面上明确出现的“主播 XX”标签。
- 不得根据人脸、声音、服装、环境或历史信息猜测身份。
- 不得把商品名、用户名、直播间标题当作主播姓名。
- 看不清时返回空，不得编造。
- 每帧分别给出姓名和可见证据，输出严格 JSON。

建议响应：

```json
{
  "frames": [
    {
      "frame_index": 0,
      "anchor_name": "小鱼",
      "label_text": "主播 小鱼",
      "visible": true
    }
  ]
}
```

## 用户界面

录播表新增“主播”列：

- 成功：`小鱼`，辅助文字 `MiniMax 自动识别`。
- 待处理：`等待识别`。
- 识别中：`正在识别`。
- 失败：`未识别`，提供重试按钮。
- 人工修改：姓名下显示 `人工确认`。

点击主播单元格可打开简洁编辑框。保存人工姓名后自动锁定，不再被后台识别覆盖。

## 错误与安全

- API Key 缺失、MiniMax 超时、FFmpeg 失败、NAS 暂不可用，只更新主播识别状态，不影响其他流程。
- 错误提示转换为小白可理解的中文，不直接展示完整服务响应或密钥。
- 图片只发送临时提取帧，不上传整段视频。
- 临时帧读取完成后立即删除。

## 验证

- 单元测试：JSON 解析、多帧一致、冲突、空结果、人工锁定。
- 数据库测试：迁移默认值、自动结果写入、人工结果不可被自动覆盖。
- 前端逻辑测试：状态文案和待识别队列筛选。
- 聚焦 Rust 和前端测试通过后，最后启动一次桌面端检查真实列表展示。
