# 候选片段发现 V2 设计

## 目标

将录播分析第一阶段改为“发现所有具有训练价值的候选片段”，不再只围绕已确认成交寻找片段。

本阶段只负责发现和保存证据，不负责与企业母稿评分，也不决定候选片段是否进入辅稿。

## 输入

- 带真实时间戳的直播逐字稿。
- 企业商品词典；没有可用商品词典时传入空数组，并要求模型将无法确认的型号标记为待确认。

## 标准输出

模型按以下结构返回：

```json
{
  "segments": [
    {
      "segment_id": "SEG-001",
      "start_time": "00:00:00",
      "end_time": "00:01:30",
      "type": "异议处理",
      "scene": "客户担心二手相机质量",
      "customer_need": "客户担心机器存在暗病",
      "original_text": "完整原话",
      "key_sentence": "最值得保留的一句话",
      "outcome": "unconfirmed",
      "interrupted": false,
      "why_selected": "为什么值得进入下一步评分",
      "evidence": [
        {
          "time": "00:00:25",
          "quote": "对应原话"
        }
      ]
    }
  ]
}
```

允许的片段类型固定为：

1. 完整成交链路
2. 高质量金句
3. 需求判断
4. 产品推荐
5. 产品讲解
6. 异议处理
7. 留人钩子
8. 信任建立
9. 售后与风险消除
10. 价格、优惠或链接承接
11. 催单与成交确认
12. 需要改进的反面案例

`outcome` 固定为：

- `confirmed_conversion`
- `conversion_signal`
- `unconfirmed`
- `no_conversion`

## 兼容策略

### 新结构是事实来源

页面展示、后续提示词和持久化状态优先使用 V2 字段：

- `type`
- `scene`
- `customerNeed`
- `originalText`
- `keySentence`
- `outcome`
- `interrupted`
- `whySelected`
- `evidenceItems`

### 旧字段只作过渡

为了不破坏现有片段列表、自动匹配和第二阶段复盘，系统继续生成以下兼容字段：

- `id`：来自 `segment_id`
- `start/end`：由 `start_time/end_time` 转成秒
- `evidence`：由证据原话合并得到
- `hook`：来自 `key_sentence`
- `reason`：来自 `why_selected`
- `product`：根据商品词典和原话提取；不确定时为“商品待确认”
- `chainStages`：只根据原话中真实出现的环节推导，不由片段类型猜测
- `verificationStatus`：第一阶段统一保持待核验，完整成交链路仍需第二阶段检查

旧的发现分、核心高光和母稿准入判断不得反向过滤 V2 候选。

## 数据处理

1. 将逐字稿按带时间戳的语义块发送给模型。
2. 模型返回 `{ "segments": [...] }`；解析器同时兼容旧版裸数组，便于平滑升级。
3. 严格校验片段类型、结果枚举、时间范围和证据。
4. 时间支持 `HH:MM:SS`、`MM:SS` 和秒数。
5. 删除无效区间，合并同类型且高度重叠的重复候选。
6. 不因链路不完整删除金句、讲解、异议处理或反面案例。
7. 切片默认优先保留 30 秒至 3 分钟；更短的金句允许保留，但必须包含可理解的上下文。

## 错误与安全边界

- 模型输出 Markdown 包裹时，从代码块中提取 JSON。
- 缺少 `segments` 时兼容旧数组；两者都无法解析时按空结果处理。
- 没有真实时间或原话证据的候选直接丢弃。
- 不根据常识补充价格、库存、链接、售后或成交。
- `confirmed_conversion` 只是模型发现结果，必须在第二阶段重新核验。
- 被打断的片段保留，并显示“受到打断”。

## 界面影响

- 左侧候选卡片展示新的 12 类片段类型。
- 卡片补充场景、关键句和“受到打断”标记。
- 第一阶段不显示“可进入母稿”结论。
- 旧存档候选继续可读，重新发现后使用 V2 结构。

## 聚焦测试

- 解析标准 `{segments: [...]}`。
- 兼容旧版 JSON 数组。
- 12 种类型均可进入候选列表。
- 四种 outcome 均能保存。
- 时间字符串正确转为秒。
- 无证据、无效时间和未知枚举被拒绝。
- 高质量金句即使链路不完整也不会被过滤。
- 反面案例不会被误标为完整成交链路。
- `interrupted: true` 能保存并展示。
- 旧字段适配不改变原始 V2 内容。

## 本轮范围

只修改录播分析页使用的候选发现流程及其领域测试。AI 助手中的整场挖样本提示词、第二阶段评分、母稿比较和辅稿入选规则留到对应提示词阶段处理。
